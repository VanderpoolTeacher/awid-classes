# Instructor Guide — Build Systems, Not Outputs

## Why this lesson exists
This is the signature idea of the whole applied approach: don't chase one-off outputs, build the
system that produces them. The "build me a course ×10" demo lands it fast — same request,
different results — so the move is to stop requesting outputs and start building the mold. Lead
with it.

## Learning objectives
1. **Explain** why one-off requests to AI produce inconsistent results. *(Understand)*
2. **Distinguish** building an output from building a repeatable system. *(Analyze)*
3. **Apply** the approach — turn a repeated task into a template + organized inputs. *(Apply)*
4. **Evaluate** which tasks are worth systematizing. *(Evaluate)*

## Materials & setup
- A chatbot on the projector for the "ask twice, compare" demo.
- The student **activity handout** printed or linked.
- Optional: a real document to strip into a template live.

## Facilitation walk-through
### 1. Open with the drift demo
Ask the chatbot for the same artifact twice; show the mismatch. Pose the shift: stop asking for
the part, build the machine that makes the part.

### 2. Teach the through-line
- **Why one-offs drift** — non-determinism; fine once, bad at scale.
- **Build the system** — machine-shop analogy; templates + rules + organized inputs.
- **Templates = source of truth** — strip to placeholders; push improvements back in.
- **Organize first** — messy in, messy out; AI can organize the mess.
- **The payoff** — costs more once, less every time; change the mold, update everything.

### 3. Live demo
Strip a real document down to a placeholder template on screen, then generate one instance from
it. Seeing the mold get built is the lesson.

### 4. Activity
Hand out the worksheet. The key step is Part 3 — pushing an improvement *into the template*, not
just fixing one output.

### 5. Discussion
Surface each learner's repeated tasks; help them judge which are worth systematizing.

### Closing thought
"Using AI like a professional isn't about clever one-off prompts — it's about building the
machine that makes consistent work, then running it."

## Check-for-understanding — answer key
1. AI is non-deterministic — a fresh, likely answer each time — so repeated requests drift in
   structure, style, and order.
2. An output is a single finished thing; a system is the reusable process (templates, rules,
   organized inputs) that produces consistent outputs repeatedly.
3. A template is a master pattern stripped to placeholders, kept as the canonical source; when
   you find an improvement, push it back into the template rather than letting one output become
   the new standard.
4. AI works best from organized inputs (messy in, messy out); if they're a mess, have AI help
   organize them first, then build on the clean base.
5. Worth a system: repeated work (weekly report, lessons, proposals). Not worth it: a genuine
   one-time task.

## Common misconceptions to watch for
- "A better prompt makes it consistent." (Consistency comes from the system.)
- "The template is my latest good output." (The template is a deliberate source of truth.)
- "Systematize everything." (Only repeated work earns the up-front cost.)

## If you have less time
Keep the drift demo, the live template-stripping, and Part 2 of the activity. Those carry the
lesson.
